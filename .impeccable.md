# Privacy Coin Design System

## Design Context

### Users
DeFi power users — experienced with wallets, transactions, and crypto UX patterns. They're bridging BTC into a privacy layer on Solana, managing shielded balances, and executing private transfers. They expect speed, precision, and zero hand-holding, but the interface must still feel approachable and not intimidating. Context: high-stakes financial actions where trust and clarity are non-negotiable.

### Brand Personality
**Private. Secure. User-friendly.**

The interface should evoke a sense of stealth and secrecy — the feeling of operating in a protected space where your financial activity is invisible to outsiders. Not paranoid or aggressive, but quietly confident. Think: a vault that opens smoothly, not a bunker you fight to enter.

### Aesthetic Direction
**Elegant dark-first with planned light mode support.**

Evolving from the current cyberpunk/neon aesthetic toward a more refined, elegant direction. Keep the signature color language (privacy green, bitcoin orange, solana purple) but apply them with more restraint — as accents rather than saturated glows. Prefer subtle depth (layered surfaces, soft shadows) over heavy glassmorphism. Animations should feel purposeful and smooth, not flashy.

**Theme strategy:** Dark mode primary, light mode planned. Design tokens and component variants should support both from the start.

**What to keep:** The privacy green (#14f195) as primary accent, bitcoin orange (#f7931a) for BTC context, the strong typographic hierarchy (Rethink Sans / Space Grotesk / Space Mono).

**What to evolve:** Reduce glow intensity, simplify gradient layering, replace scan-line/grid effects with cleaner spatial separation. Glassmorphism used sparingly — reserve for elevated surfaces only.

**Anti-patterns to avoid:** Overly techy/hacker aesthetic, aggressive neon saturation, cluttered dashboards, generic DeFi template look, anything that feels like a game rather than a financial tool.

### Design Principles

1. **Quiet confidence** — The interface communicates security through polish and clarity, not through locks, shields, or warning icons. Trust is built by things working flawlessly.

2. **Progressive disclosure** — Show only what's needed for the current action. Advanced details (proof status, nullifiers, tree indices) are available but never in the way. Power users can dig deeper; the surface stays clean.

3. **Purposeful motion** — Every animation earns its place. Transitions communicate state changes (shielding, proving, confirming). No decorative animation that doesn't serve comprehension.

4. **Color with intent** — Privacy green = shielded/private actions. Bitcoin orange = BTC context. Solana purple = network/ecosystem. Gray = neutral/inactive. Never use color decoratively — it always signals meaning.

5. **Elegant restraint** — When in doubt, remove. Fewer borders, less glow, more whitespace. Let content breathe. A premium financial tool, not a crypto dashboard.

### Light Mode (Planned)
When implementing light mode, invert surface hierarchy while preserving accent colors at adjusted brightness. Privacy green and bitcoin orange should darken slightly on light backgrounds for contrast. Target WCAG AA (4.5:1) for all text.

## Component Guidelines

### Cards & Surfaces
- Use layered backgrounds (bg → card → secondary) for depth hierarchy
- Reserve glassmorphism (backdrop-blur) for modals and elevated overlays only
- Borders: subtle (opacity 10-15%), not decorative
- Shadows: soft, multi-layered for depth — avoid harsh drop shadows

### Buttons
- Primary: privacy green with subtle gradient, slight hover lift
- Bitcoin context: bitcoin orange variant
- Secondary: muted background, no glow
- Ghost: transparent, minimal — for toolbar/nav actions
- All buttons: 300ms transitions, subtle press feedback (scale 0.97)

### Inputs
- Clean borders, generous padding
- Color-coded focus rings matching context (privacy/btc/sol)
- Monospace font for addresses and amounts
- Clear error states with inline messaging

### Motion
- Default duration: 200-300ms
- Easing: ease-out for enters, ease-in for exits
- Stagger: 50ms between list items
- Proof/transaction states: use progress indication, not decorative animation
- Respect `prefers-reduced-motion`

## Accessibility Targets

- WCAG AA compliance (minimum)
- All interactive elements keyboard-accessible
- Focus indicators visible and consistent (ring-2, offset-2)
- Color never the sole indicator of state — pair with icons or text
- Support `prefers-reduced-motion` for all animations
- Touch targets: minimum 44x44px on mobile
