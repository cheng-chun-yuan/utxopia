# Product

## Register

product

## Users

UTXOpia is for crypto users who already understand wallets, transactions, bridges, and network environments. They use the app to deposit Bitcoin, manage shielded notes, send private transfers, and withdraw back to Bitcoin or a native chain path. The context is high-stakes financial activity, so the interface must prioritize clarity, predictable state, and explicit network context.

## Product Purpose

UTXOpia is a privacy-preserving Bitcoin bridge and shielded transfer interface. It turns deposits into private commitments, lets users transact through zero-knowledge proofs, and keeps advanced protocol details available without putting them in the main workflow. Success means users can identify the active chain and environment, sign in or connect, deposit, send, and review activity without parsing implementation details.

## Brand Personality

Private. Precise. Calm.

The product should feel like a serious financial tool: quiet, secure, and technically capable. It can keep the existing dark visual language, but network color should communicate context rather than decoration.

## Anti-references

Avoid generic DeFi dashboards, loud cyberpunk neon, decorative hacker motifs, overloaded technical panels, and copy that exposes internal protocol machinery before the user needs it. For Sui surfaces, avoid purple and green as the dominant visual language; use a restrained blue chain context.

## Design Principles

1. Keep primary workflows obvious: deposit, send, activity, and sign-in should be visible before advanced configuration.
2. Disclose technical details progressively, with object IDs, proofs, and network diagnostics behind secondary affordances.
3. Use color as chain context and state, not decoration.
4. Preserve user trust through stable layout, concise copy, clear errors, and visible network selection.
5. Make Solana and Sui feel like variants of one product, not separate microsites.

## Accessibility & Inclusion

Target WCAG AA contrast, keyboard-accessible controls, visible focus states, and touch targets of at least 44px where practical. Motion should communicate state and respect reduced-motion preferences.
